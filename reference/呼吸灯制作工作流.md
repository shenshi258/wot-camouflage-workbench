# 独立模型呼吸灯制作工作流

适用于 WOT 涂装中随车辆运动的装饰呼吸灯。参考本项目 SFAC105 R2 的实现；原生接口与参数依据欧服 2.4.1.0，迁移客户端或车型前重新核对。与 [整车加载兼容性工作流](整车加载兼容性工作流.md) 一起执行。

面向使用者的独立说明见 [呼吸灯制作方法](../改造区/呼吸灯制作方法.docx)。从没有灯效的模型开始，见 [从零制作渐变呼吸灯图文教程](../改造区/从零制作渐变呼吸灯图文教程.docx)。本文件保存制作约束、排错经验和验收要求。

## 1 制作路径

采用“独立灯面模型 → 原生 emissive_playground 材质 → .seq 序列 → 车辆挂点”的结构。原车继续使用既有整车材质，呼吸变化由附加模型的原生着色器执行。

1. 保存原包、客户端路径、区服和版本，确认原包基线，记录 SHA256。
2. 逐个识别发光材质对应的 primitiveGroup、顶点、索引、UV、贴图及骨骼权重。只提取灯面，不复制整个车体。
3. 将灯面转换到目标挂点的局部空间，导出独立 nodeless 模型。蒙皮灯面转换时保留运动含义，不能把任意多骨骼网格按静态网格处理。
4. 配置原生呼吸材质，建立 .seq 和运行时挂载、可见性、清理逻辑。
5. 确认独立灯效能显示后，再关闭对应的原常亮灯面，避免两层叠加掩盖变化。黑贴图替换仅限已选灯材质，不可扩展到履带或车体材质。
6. 打包完整替换包，检查全部依赖和修改范围，绑定最终哈希进行离线及游戏验证。

## 2 原生材质参数

### 从没有灯效的模型开始

- 先新建独立灯面和 UV，再制作颜色渐变并烘焙为 emissionMap；不得要求用户必须先有 glow 材质才能制作。普通车体材质、履带、蒙皮和节点保持原样。
- 新增灯面与承载表面保留适当间距，避免共面闪烁；间距按实际模型单位和比例确定。UV 方向、色标顺序、DDS alpha 和 mip 单独检查。
- 区分灯面上的空间颜色渐变、同一位置随时间换色、以及整体亮度呼吸。固定渐变加呼吸可使用彩色 emissionMap 与同步 Pulse；循环换色须另外验证原生变色模式和通道偏移，不能照搬 Blender Hue 动画。
- Blender 节点、关键帧和 Cycles 曲线仅用于制作预览。先在 Strength=1 时烘焙颜色，导出游戏资源时由原生材质重新实现呼吸；不得声称 .blend 动画自动进入游戏。
- 新网格先转换到实际挂点的局部空间，再导出独立模型。刚性导出器不能用于任意蒙皮灯面；重新检查顶点格式、索引、包围盒和全链依赖。
- 原模型没有常亮灯时，跳过“关闭原灯”步骤，不添加无意义的透明黑替换，也不改原车整车着色器。
- 图文教程使用真实制作界面截图，并明确区分 Blender 预览、离线资源检查和游戏内观察。示例资产不等于已完成定位和整车验收的安装包。

### 参数参考

使用 `shaders/custom/emissive_playground.fx`。本次参考值：

| 参数 | 值 | 约束 |
| --- | --- | --- |
| animationMode | 2 | 当前客户端定义 Pulse=2、Pattern=1，必须核对原生枚举 |
| emissionMap | 原灯光贴图 | 保留原图案与颜色 |
| usePhaseMap / phaseMap | true / 纯白 DDS | 本次用于统一灯面相位 |
| speed / waveLen | 1.3333333333 / 1 | 本次离屏结果为约 3 秒一周期；不要推广为所有着色器通用公式 |
| g_tint | 1.5 1.5 1.5 1（R4） | 唯一实测线性可控的亮度倍率，不截断；R3=1 峰值 1.4、R4=1.5 峰值 2.1；alpha 分量保持 1 |
| g_forwardMult / g_deferredMult | 2 / 2 | **实测无效**：交付材质实际选中的 Pulse+phaseMap 分支把它们编译为 [unused]，改值输出不变；提亮不要用它们 |
| g_offsetBlack / g_offsetBlackFwd | 0.4 / 0.4 | 暗部参数；不能直接说屏幕最低亮度必为 40% |
| g_contrast / g_zeroPhaseLum | 1 / 1 | 保持本次曲线基准 |
| useVersicolorMode | false | 关闭变色 |
| g_chromaOffsetGreen / g_chromaOffsetBlue | 0 / 0 | 避免通道相位差导致色偏 |
| doubleSided | true | 双面灯片 |
| srcBlend / destBlend | 3 / 6 | 本灯面使用的混合设置，换素材时重新验证 RGB 与 alpha |

`g_enableVisTunnel=false`、`g_enableEnvMultiplier=false` 和 `angleFalloffParams=1 1 1 0` 同样来自本次配方。亮度调整只用 `g_tint`：`g_zeroPhaseLum`、`g_contrast`、`g_forwardMult`、`g_deferredMult` 在本材质的 Pulse 分支上实测无效，`g_offsetBlackFwd` 只抬部分分支的暗相，会造成分支间亮度不一致。开镜隐藏由运行时可见性处理，不能只依赖材质可见性隧道参数。

必须测试最终材质选择的真实模式。不得手动挑选 Pulse 像素着色器渲染成功后，忽略材质实际设置成 Pattern 的问题。离屏检查同时记录原生枚举来源、最终包参数和使用的分支。

## 3 模型和序列

- `.model` 使用 `nodelessVisual` 指向独立模型基名。
- `.visual_processed` 引用自己的顶点/索引段、材质、包围盒和 geometrySize。
- 本次独立模型匹配蜘蛛桶形特效使用的处理后静态顶点格式 `BPVTxyznuv` / `set3/xyznuvpc`，顶点跨度 24 字节。不要仅凭扩展名判断格式。
- `.seq` 使用空资源 Root 和独立 Light 模型，明确位置、旋转、缩放，关闭投影。当前参考结构 `duration=0.0`；约 3 秒周期由着色器决定，不是 sequence 的 duration。
- 本次共 24 个灯模型，14 处为双节点轮边灯。数量和锥顶仿射处理都属于该涂装特征，换车时重新提取。

## 4 挂载与生命周期

保留原生 `camouflages.getModelAnimatorsPrereqs`、`getModelAnimators` 的返回内容，只追加本车型所需资源和动画器。通过 `AnimationSequence.Loader` 加载序列，用 `ModelWrapperContainer` 绑定独立空模型。

车辆节点只提供位置和运动参照。层级采用：车辆原节点 → 自有空模型 mount → 自有变换节点 → 序列根模型 → 灯效。将轮边校正矩阵传入自有空模型的节点，不对原车共享车轮或履带节点设置变换。

挂点必须是承载对应关节的节点，不能用部件别名代替：炮管灯挂 `Gun`（客户端 `TankNodeNames.GUN_INCLINATION`，由 `appearance.gunMatrix` 驱动），炮塔/车体灯才使用 `turret`/`hull` 这类部件别名。别名只保证静止位置，不跟随关节动画。蒙皮灯面按骨骼节点空间烘焙，运行时挂的节点必须与烘焙用的骨骼基节点一致；改名或换节点前先核对节点局部变换是否为单位矩阵，否则灯面会整段位移。

本次 14 处灯面符合刚性底面加混合权重锥顶的条件，可用仿射校正复现。必须先验证全部顶点符合该模型；一般多骨骼网格应另做适当蒙皮处理，不能套用这个近似。

车辆构建阶段本车 appearance 可能尚未就绪。可以先构建并保持隐藏，随后确认本车身份和可见性；不得因首次判断未就绪而永久漏挂。按该方案范围过滤车型和本车，不扩展到其他车辆。

切车、停用或销毁时，停止序列、取消回调、卸载自有根模型。重复 start/stop 不应产生重复挂载；加载失败需清理已创建对象，不中断原生整车流程。初始化阶段读取不到节点矩阵时采用有限重试，不无限输出逐帧错误。

## 5 开镜和场景可见性

原生 `Vehicle.show(False)` 可能保留 `ShadowPassBit`，此时 visible 非零并不代表车体应该显示。同步 `changeVisibility`、`changeDrawPassVisibility` 与 `skipColorPass` 所表达的颜色绘制状态到独立模型及序列启用状态。

要求开镜立即隐藏、退镜恢复、场景隐藏后正确恢复。对未完成构建或已销毁的 appearance 保持隐藏。不得为显示灯效而写回车辆本身的可见性标志或履带状态。

## 6 本次排错经验

| 现象 | 已知证据 | 后续制作要求 |
| --- | --- | --- |
| 只变暗而不呼吸 | R1 将 animationMode 设为 Pattern 的 1；旧离屏测试绕过模式选择 | 从客户端元数据确认 Pulse 枚举，检查包中实际值 |
| 开镜出现装饰遮挡 | R1 未将车辆颜色绘制状态传播到独立灯效 | 单列开镜、退镜及场景恢复验收 |
| 履带消失 | 用户确认车库和战斗均发生；具体现场根因未证明 | 自有节点承载灯面变形，原车网格、履带材质和节点只读对照；不要把可疑交互写成已证实根因 |
| 炮管分组错误持续刷屏 | 原包已有索引缓冲只有1组但 visual 引用第1组的问题，有效组为0 | 检查全部网格分组；本例移除不存在分组的引用，不能把1直接改成0造成重复绘制 |
| 炮管灯不随俯仰 | R2 将炮管灯挂在部件别名 `gun`；客户端以 `TankNodeNames.GUN_INCLINATION`（值 `Gun`）承载 appearance.gunMatrix 的俯仰 | 蒙皮灯面按骨骼节点空间烘焙后，运行时必须挂同一个节点；部件名只用于 `addPart` 别名，不参与关节动画 |
| 有加载或绑定日志但效果不对 | 直接控制原整车材质的版本已出现此现象 | 加载、绑定、可见效果分开验收 |
| 离屏通过但整车闪退 | 早期改整车材质/着色器的版本出现 Compound 构建失败 | 独立记录文件、离屏、实际整车验证；不得用前两项替代游戏证据 |

## 7 验证和记录

必须检查最终包的 ZIP CRC、无压缩、大小写重复路径，全部 `.seq → .model → visual → primitives → texture/shader` 依赖，以及四个车体部件和独立模型的全部网格分组范围。对照原包的车体节点、蒙皮、履带材质、贴图和原始几何，分别登记有意改动。

离线检查至少覆盖实际枚举与渲染分支、多周期 RGB/alpha、局部空间与运动姿态、开镜隐藏/恢复、首次加载未就绪、切车清理及失败回退。API 模拟只证明被模拟逻辑，不证明引擎实际挂载行为。

游戏中检查车库初次加载、重复切车/重启、完整呼吸循环、移动履带/悬挂、炮塔/炮管运动、开镜/退镜、远近 LOD、适用渲染分支及本次日志。先解决阻塞性错误再扩大测试范围，保存滚动日志中与本次版本有关的证据。

用户要求自己测试时交付包和必要说明，不启动或操作游戏。用户反馈“完成”等总结性结果可以记录为用户反馈，不据此补写没有明确记录的逐项验收。状态仍按整车工作流执行；失败版本保留 failed，不覆盖失败证据。

## 8 复用入口

当前工程位于 `改造区/SFAC105_呼吸灯工程/蜘蛛独立特效版_R4/`（炮管灯挂 Gun 倾角节点；R2 保留为失败记录）：

- `build_spider_breathing.py`：提取灯面、创建资源、编译脚本、打包（`TINT` 即整体亮度倍率）。
- `mod_sfac105_spider_breathing.py`：挂载、运动校正、可见性与清理模板。
- `validate_spider_gpu.py`：最终材质模式及原生像素着色器离屏验证；同一程序渲染两次（交付参数与 tint=1 基准），逐像素比值必须等于材质倍率。
- `validate_spider_runtime.py`：最终 Python 2.7 字节码的挂载与状态模拟（含炮管俯仰随动与挂点回退）。
- `verify_spider_package.py`：完整依赖、所有分组、挂点存在性与修改范围检查。
- `sweep_brightness.py`：亮度参数扫描，输出 `亮度参数扫描.json`；新增亮度方案时先跑它，确认哪些参数在交付分支上真正生效。

继续修改时先建立新修订目录并更改输出文件名，保留既有交付包和记录。构建会生成新包和新哈希，必须重新执行对应验证；不得把旧版本的结论复制成新版本的通过状态。
